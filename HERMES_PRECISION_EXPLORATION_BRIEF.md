## Precision ladder
Implement several genuinely distinct runnable precision levels, rather than just changing flags with no numerical effect. Use profiling and model sensitivity to choose practical candidates. A sensible ladder to investigate:
1. Current best f32/FMA baseline control (unchanged).
2. Conservative mixed FP16/BF16: lower precision for suitable large matrix/convolution operations; retain f32 accumulation/reductions and sensitive duration/F0/phase/noise operations where needed. State which dtype(s) actually implemented and why.
3. More aggressive mixed/low-precision coverage, distinguish compute, weights, activations, accumulation and f32 islands. This should be materially different from level2; do not force an unstable or unsupported all-half model.
4. Quantized candidate, e.g. INT8 weights and/or activations with documented scales/calibration and runtime kernels. Explore lower-bit weight quantization (e.g.INT4) only if feasible and potentially useful on4090; weight compression alone is NOT proof of faster compute. Label weight-only/dequantized approaches precisely.

This is guidance, not a demand to pretend every dtype or bit-width works. Deliver several measured levels where feasible; record attempted failures, unsupported paths and slower variants honestly.
